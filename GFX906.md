# gfx906 (AMD Instinct MI50/MI60) build notes

This fork carries the minimum changes needed to build a ROCm 10 distribution from
TheRock targeting `gfx906` only, which isn't an officially supported target upstream
(official support starts at gfx908).

## Source changes

None. This fork currently carries no source changes vs upstream `main`; it only adds
this document.

Earlier revisions force-disabled the `rccl-translate` gfx1250-unbundle step in
`comm-libs/CMakeLists.txt`, because it failed with
`No code objects for architecture 'gfx1250'` when RCCL was scoped to gfx906 only.
Upstream fixed this properly in ROCm/TheRock#8279 (the pretranslate step is now
skipped when gfx1250 isn't in RCCL's target list), so the local hack was dropped.

## Build recipe (Linux / WSL2 Ubuntu 24.04)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# meson 1.12.0's duplicate --version-script regression is fixed upstream
# (ROCm/TheRock#7287, #7489); pin meson==1.11.2 only if you hit it again.
python3 ./build_tools/fetch_sources.py

eval "$(./build_tools/setup_ccache.py)"
export CMAKE_BUILD_PARALLEL_LEVEL=4   # -j on the CLI does NOT propagate to nested
                                       # per-subproject `cmake --build` calls; this
                                       # env var does, and is what actually caps
                                       # parallelism enough to avoid OOM on a 20-core/
                                       # limited-RAM WSL VM.

cmake -B build -GNinja \
  -DTHEROCK_AMDGPU_FAMILIES=gfx906 \
  -DTHEROCK_TEST_AMDGPU_TARGETS=gfx906 \
  -DCMAKE_C_COMPILER_LAUNCHER=ccache \
  -DCMAKE_CXX_COMPILER_LAUNCHER=ccache

ninja -C build -j4
ninja -C build artifacts
ninja -C build archives
```

Output: `build/dist/rocm/` — a self-contained ROCm 10 install tree for gfx906.

## Notes

- `THEROCK_TEST_AMDGPU_TARGETS=gfx906` (not the default, which builds RCCL for ~24
  architectures) scopes RCCL to gfx906 only — this is what you want if you just need
  multi-GPU communication between MI50/MI60 cards and don't care about other archs.
- `./build_tools/fetch_sources.py` resets all submodules and reapplies patches — it is
  **destructive** to any uncommitted submodule changes. Commit first.
- Long builds should be detached with `setsid nohup ... & disown` (not plain `&`) if run
  inside a `wsl.exe` invocation from a Windows host, or they die when the parent process
  exits.
